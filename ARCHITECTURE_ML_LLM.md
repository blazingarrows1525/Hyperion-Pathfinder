## 1. End-to-End System Architecture

Resume Checker operates on a dual-pipeline topology:
1. **Offline Knowledge Extraction & Unsupervised Genome Pipeline:** Converts heterogeneous student/alumni PDF resumes into cleaned corpora, dense vector embeddings, clustered career archetypes, and an indexed FAISS vector database.
2. **Online Real-Time Inference & LangGraph RAG Workflow:** Ingests live candidate resume PDFs and target job descriptions (JDs), executes stateless PDF extraction, retrieves semantically aligned alumni precedents, and generates structured benchmarking reports via GitHub AI Inference (`openai/gpt-4o-mini`).

```mermaid

    subgraph "OFFLINE PIPELINE (Data & ML Clustering)"
        A["Resumes/*.pdf"] -->|process_resumes.py (pypdf)| B["processed_data/resume_text_data.csv"]

        C -->|vectorize_resumes.py (all-MiniLM-L6-v2)| D["resume_embeddings.npy (226 x 384)"]
        D -->|cluster_resumes.py (K-Means k=5)| E["resume_clustered_data.csv"]
        E -->|label_clusters.py (TF-IDF)| F["Archetype Keywords (50/cluster)"]
        E & D -->|build_vector_store.py| G["vector_store/benchmark_resumes.index & .pkl"]
    end

    subgraph "ONLINE PIPELINE (FastAPI + LangGraph + LLM)"
        H["Candidate PDF + Target JD"] -->|POST /analyze| I["FastAPI (main.py)"]
        I -->|initial_state| J["LangGraph StateGraph (graph.py)"]

            P -- No --> Z
        end

    end
```

## 2. Exhaustive File-by-File Technical Audit

### 2.1 Backend Core & Inference Pipeline

#### `models.py`
- **Purpose:** Declares the shared state schema for the LangGraph workflow.
- **Key Class:** `GraphState(TypedDict)`
- **Current Attributes:**
  | Field | Type | Role | Lifecycle |
  | :--- | :--- | :--- | :--- |
  | `userId` | `Optional[str]` | Deprecated legacy field; retained for structural compatibility. | Set to `None` |
  | `job_description` | `str` | Raw text of target Job Description entered by candidate. | Ingested at endpoint; persistent |
  | `file_bytes` | `Optional[bytes]` | Raw binary stream of the uploaded resume PDF. | Ingested at endpoint; deleted in `extract_text` to conserve memory |
  | `resume_text` | `Optional[str]` | Plain extracted UTF-8 text from the candidate's PDF. | Created by `extract_text`; consumed by `generate_feedback` |
  | `target_archetype` | `Optional[str]` | Resolved career archetype derived from nearest alumni vectors. | Set by `find_relevant_resumes`; injected into system prompt |
  | `alumni_examples` | `Optional[str]` | Concatenated text snippets of top-3 matching alumni resumes. | Formatted in `find_relevant_resumes`; injected into user prompt |
  | `feedback` | `Optional[str]` | Complete Markdown response generated by the LLM. | Populated by `generate_feedback` |
  | `error_message` | `Optional[str]` | Fault flag; if non-empty, triggers early termination to `END`. | Evaluated by `did_process_fail` conditional edges |
- **Architectural Debt / Gaps:** State is strictly untyped text. It lacks discrete numerical fields (`score: int`), structured skill arrays (`matched_skills: List[str]`, `missing_skills: List[str]`), or confidence vectors.

---

#### `services.py`
- **Purpose:** Core service layer containing model loaders, RAG retrieval logic, LangGraph node workers, and external LLM client callers.
- **Key Functions:**
  1. `load_models_and_store()`:
     - Implements `@lru_cache(maxsize=1)` singleton pattern.
     - Reads `vector_store/benchmark_resumes.index` via `faiss.read_index`.
     - Deserializes `vector_store/benchmark_resumes.pkl` via `pickle.load`.
     - Initializes `SentenceTransformer('all-MiniLM-L6-v2')`.
  2. `get_github_ai_client()`:
     - Implements `@lru_cache(maxsize=1)`.
     - Reads `GITHUB_TOKEN` from environment.
     - Initializes `azure.ai.inference.ChatCompletionsClient(endpoint="https://models.github.ai/inference", credential=AzureKeyCredential(token))`.
  3. `extract_text(state: GraphState) -> GraphState`:
     - Reads `state["file_bytes"]` into `io.BytesIO`.
     - Instantiates `pypdf.PdfReader`. Checks and decrypts empty-password encrypted PDFs (`reader.decrypt('')`).
     - Extracts per-page text into a single newline-separated string.
     - Deletes `file_bytes` from state to free memory buffers.
  4. `find_relevant_resumes(state: GraphState) -> GraphState`:
     - Encodes `state["job_description"]` using `model.encode([query], normalize_embeddings=True)`.
     - Converts vector to `np.float32`. Checks dimension alignment with `index.d` (384).
     - Calls `distances, indices = index.search(query_vector, k=5)`.
     - Inspects top-1 valid index to determine `target_archetype`.
     - Loops through retrieved indices and collects up to 3 alumni resume text snippets matching `target_archetype`.
  5. `generate_feedback(state: GraphState) -> GraphState`:
     - Constructs structured prompt with `SystemMessage` (Resume Career Coach persona, Markdown layout enforcement) and `UserMessage` (Resume + JD + Alumni snippets).
     - Dispatches synchronous completion to `openai/gpt-4o-mini` on GitHub Models.
     - Sets `state["feedback"] = response.choices[0].message.content`.
  6. `did_process_fail(state: GraphState) -> str`:
     - Evaluates `bool(state.get("error_message"))`. Returns `"yes"` if failed, `"no"` if healthy.
- **Architectural Debt / Gaps:**
  - **Vector Normalization Asymmetry:** Query vector is normalized (`normalize_embeddings=True`), but the stored FAISS index was created using Euclidean $L_2$ (`IndexFlatL2`) without normalized vectors.
  - **Single-Sample Archetype Resolution:** The archetype is determined solely by `indices[0][0]`. A single outlier sample can misclassify the entire candidate profile.
  - **Non-Streaming LLM Call:** `client.complete()` is executed synchronously without `stream=True`, buffering the entire LLM completion before returning to the web stream.

---

#### `graph.py`
- **Purpose:** Compiles the LangGraph `StateGraph` state machine for execution.
- **Key Functions:**
  - `get_graph()`:
    - Instantiates `workflow = StateGraph(GraphState)`.
    - Nodes: `extract_text`, `find_relevant_resumes`, `generate_feedback`.
    - Edges:
      - Entry Point $\rightarrow$ `extract_text`
      - `extract_text` $\rightarrow$ `services.did_process_fail` $\rightarrow$ `{"yes": END, "no": "find_relevant_resumes"}`
      - `find_relevant_resumes` $\rightarrow$ `services.did_process_fail` $\rightarrow$ `{"yes": END, "no": "generate_feedback"}`
      - `generate_feedback` $\rightarrow$ `services.did_process_fail` $\rightarrow$ `{"yes": END, "no": END}`
    - Returns compiled `app_graph`.
- **Architectural Debt / Gaps:** Linear pipeline without retry loops, fallback model routes, or parallel evaluation branches (e.g., scoring node running parallel to recommendation node).

---

#### `main.py`
- **Purpose:** FastAPI REST gateway serving health diagnostics, CORS negotiation, and streaming analysis endpoints.
- **Key Endpoints & Functions:**
  - `GET /health`: Probes status, model identifier, and checks `hasattr(app.state, 'graph')`.
  - `GET /`: Basic API root banner with link to Swagger docs.
  - `POST /analyze`:
    - Parameters: `job_description: str` (Query param), `resume_file: UploadFile` (Multipart form file).
    - Validates presence of bytes.
    - Sets initial state: `{"job_description": job_description, "file_bytes": file_bytes}`.
    - Configures LangGraph runtime config: `{"configurable": {"thread_id": "stateless_thread"}}`.
    - Invokes `app.state.graph.astream(...)`.
    - Returns `StreamingResponse(stream_graph_response(response_stream), media_type="text/plain; charset=utf-8")`.
  - `stream_graph_response(response_stream)`:
    - Async generator that consumes LangGraph stream chunks.
    - Captures `chunk["generate_feedback"]["feedback"]` or accumulated `error_message`.
    - Yields final text payload.

### 2.2 Offline Data Preprocessing & Unsupervised ML Pipeline

#### `process_resumes.py`
- **Purpose:** Ingests raw alumni resume PDFs from `Resumes/`, extracts raw textual tokens, and outputs tabular dataset.
- **Input:** Directory `Resumes/*.pdf`
- **Output:** `processed_data/resume_text_data.csv` (`file_name`, `file_path`, `extracted_text`)
- **Key Dependencies:** `pypdf.PdfReader`, `pandas`, `tqdm`.
- **Limitation:** Fails to parse complex multi-column layout flows and scans without embedded font glyphs (image-only PDFs).

#### `clean_text.py`
- **Purpose:** Applies NLP sanitization regex to standardize resume vocabulary.
- **Transformations:**
  1. URL removal: `re.sub(r'https?://\S+|www\.\S+', '', text)`
  2. Email removal: `re.sub(r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b', '', text)`
  3. Character whitelisting: `re.sub(r'[^\w\s\.\+#-]', '', text)` (preserves C++, C#, .NET)
  4. Lowercasing: `text.lower()`
  5. Whitespace consolidation: `re.sub(r'\s+', ' ', text).strip()`
- **Input:** `processed_data/resume_text_data.csv`
- **Output:** `processed_data/resume_cleaned_data.csv` (`file_name`, `extracted_text`, `cleaned_text`)

#### `vectorize_resumes.py`
- **Purpose:** Dense vector embedding generation using MiniLM.
- **Model:** `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions).
- **Process:** Iterates over `cleaned_text`, executes `model.encode(texts_to_embed, show_progress_bar=True)`.
- **Output:**
  - `processed_data/resume_embeddings.npy` (Numpy array, shape `(226, 384)`, dtype `float32`).
  - `processed_data/resume_embedded_data.csv` (adds `embedding_id` index column).

#### `cluster_resumes.py`
- **Purpose:** Cluster discovery and 2D projection visualization.
- **Workflow:**
  1. **Elbow Method:** Fits `KMeans(n_clusters=k, init='k-means++', random_state=42, n_init=10)` for $k \in [1, 20]$. Computes Within-Cluster Sum of Squares (Inertia). Saves `elbow_plot.png`.
  2. **Optimal Cluster Fitting:** Configured with `OPTIMAL_K = 5`. Fits final K-Means model, outputs `archetype_cluster` column (integers $0 \dots 4$).
  3. **t-SNE Projection:** `TSNE(n_components=2, random_state=42, perplexity=min(30, N-2))`. Projects 384D to 2D (`tsne-x`, `tsne-y`). Saves `cluster_visualization.png`.
- **Output:** `processed_data/resume_clustered_data.csv`.

#### `label_clusters.py`
- **Purpose:** Keyword extraction per cluster to enable human interpretation and domain labeling.
- **Algorithm:** Term Frequency-Inverse Document Frequency (TF-IDF).
- **Parameters:** `TfidfVectorizer(stop_words='english', max_features=1000)`.
- **Metric:** Computes mean TF-IDF weight across cluster documents:
  $$\text{Score}(w, C_k) = \frac{1}{|C_k|} \sum_{d \in C_k} \text{TF-IDF}(w, d)$$
- **Output:** Console output displaying top 50 discriminative keywords for clusters $0 \dots 4$.

#### `build_vector_store.py`
- **Purpose:** Merges vector matrices, domain labels, and raw text into production FAISS index and metadata store.
- **Taxonomy Mapping (`ARCHETYPE_MAP`):**
  - `0`: `"Core Engineering & Business"`
  - `1`: `"Data Science & AI/ML"`
  - `2`: `"General CS & Software Development"`
  - `3`: `"Full-Stack Web Development"`
  - `4`: `"Core Engineering (Mechanical/Civil)"`
- **Index Architecture:**
  - `faiss.IndexFlatL2(d=384)`: Exact exhaustive Euclidean search.
  - `faiss.IndexIDMap`: Maps vector positions to dataframe `embedding_id`.
  - Vectors added: 226 entries.
- **Metadata Serialization:**
  - Format: Pickled list of dictionaries:
    ```python
    [{
      'file_name': str,
      'text': str,         # Cleaned resume text
      'archetype': str     # Mapped archetype label
    }, ...]
    ```
- **Output:** `vector_store/benchmark_resumes.index` and `vector_store/benchmark_resumes.pkl`.

## 4. In-Depth ML & NLP Component Analysis

### 4.1 Embedding Space (`all-MiniLM-L6-v2`)
- **Base Architecture:** 6-layer MiniLM distilled from BERT-base.
- **Sequence Length Limit:** 256 WordPiece tokens (longer resumes are silently truncated at token 256 during vectorization unless chunked).
- **Dimensionality:** 384-dimensional dense vectors.
- **Pooling Strategy:** Mean pooling of contextualized token representations.

### 4.2 Distance Metric & Mathematical Divergence
- **Vector Store Construction:** Built with `IndexFlatL2`:
  $$D_{L2}(u, v) = \|u - v\|_2 = \sqrt{\sum_{i=1}^{384} (u_i - v_i)^2}$$
- **Online Query Embedding:** Generated with `normalize_embeddings=True`:
  $$\|q\|_2 = 1.0$$
- **Issue:** The saved alumni vectors in `benchmark_resumes.index` were **not** normalized prior to index insertion in `build_vector_store.py`. While Euclidean distance on unnormalized vectors preserves magnitude (e.g., word frequency/document density), querying with a unit vector causes directional skewing.
- **Recommendation:** Convert both indexing and search to Inner Product (`IndexFlatIP`) with strict unit normalization ($\|v\|_2 = 1$), which mathematically guarantees exact Cosine Similarity:
  $$\text{Cosine Similarity}(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2} = u_{norm} \cdot v_{norm}$$

## 5. LangGraph & LLM Orchestration Audit

### 5.1 Graph State Machine

```
[Start] --> extract_text --> did_process_fail?
                                 |-- Yes --> [END]
                                 |-- No  --> find_relevant_resumes --> did_process_fail?
                                                                           |-- Yes --> [END]
                                                                           |-- No  --> generate_feedback --> did_process_fail?
                                                                                                                 |-- Yes --> [END]
                                                                                                                 |-- No  --> [END]
```

### 5.2 Current Prompt Strategy (`services.py`)
- **System Prompt:**
  ```text
  You are an expert Career Intelligence Engine Career Coach analyzing a student's resume.
  The target role seems to be related to '{target_archetype}'.
  Analyze the user's resume against their target job description and these examples from successfully placed placed alumni.
  Also mention where these things are been compared to alumni's resumes.

  Provide feedback in this structure ONLY (use Markdown):
  **1. Overall Score (out of 100):** [Your Score Here]
  **2. What's Good:** (2 bullet points)
  **3. Actionable Recommendations:** (3 bullet points linking to JD/Alumni)
  **4. Key Skills to Add:** (3 bullet points from JD)
  ```
- **Vulnerabilities:**
  1. *Lack of Schema Enforcement:* The model may generate scores as `"85/100"`, `"Score: 85"`, or `"85%"`, requiring regex parsing on the frontend.
  2. *Hallucination of Placement Probabilities:* Without explicit grounding constraints, the model can make unverified claims about placement odds.
  3. *Unanchored Scoring:* No rubric is provided to define what constitutes a score of 60 vs 85 vs 95.
